# LAST OUTPOST · 최후의 방어선

카톡 방 링크로 함께하는 1~4인 실시간 좀비 타워 디펜스. 혼자서도 같은 규칙으로 시작합니다. 화폐 단위는 **찌**입니다.

## 실행

Node.js 24 이상이 필요합니다.

```sh
npm ci
npm start
```

기본 포트는 `3000`, 바인딩 주소는 `0.0.0.0`입니다. 환경 변수 `PORT`, `HOST`로 변경할 수 있습니다. 서버 준비 확인은 `GET /health`가 반환하는 `{"ok":true}`를 사용합니다. 별도 DB, API 키, 카카오 로그인은 필요하지 않습니다.

## 플레이

1. 닉네임을 입력해 방을 만듭니다. 친구 초대 버튼으로 방 URL을 복사·공유합니다.
2. 아래 시설을 선택하고 전장의 경로·건물 밖 빈 곳을 누릅니다. 한 방에 최대 100개 시설을 배치합니다.
3. 자신의 시설을 선택해 4단계까지 강화하거나 투자액의 75%에 판매합니다. 강화 후 수치와 비용이 표시됩니다.
4. 방어 시작을 누르면 준비 시간 이후 웨이브가 자동 진행됩니다. 군인 기지는 병사를 자동 출격시키며 시설당 최대 4명이 활동합니다.
5. 은행은 웨이브를 완료할 때 소유자에게 수익을 지급합니다. 기본 처치 보상은 실제 피해 기여에 따라 배분되고 웨이브 보상은 각자 받습니다.
6. 매 10웨이브의 보스를 처치하고 남은 적까지 처리하면 다음 맵으로 이동합니다. 건설·강화 지출을 각 소유자에게 **전액** 환급하고 시설과 병사는 비웁니다. 돈·해금·전체 웨이브 번호는 유지됩니다.
7. 기지 공동 체력이 0이 되면 종료됩니다. 새 작전 시작으로 새 방을 만들 수 있습니다.

지역은 폐허 도시 → 폐쇄 공장 → 군사기지 → 검역 항만 → 오염 연구소 순으로 순환하며 난이도는 계속 상승합니다. 보스는 장갑, 재생, 돌진, 증원, 오염의 지역별 특성을 가집니다. 웨이브는 무한하지만 숫자·자원 한계가 없는 서버를 뜻하지는 않습니다. 현재 밸런스는 첫 플레이용이며 고웨이브 장기 플레이의 조정이 필요할 수 있습니다.

소유한 시설만 강화·판매할 수 있습니다. 보급소의 공격력 지원과 의무소의 회복은 같은 종류의 여러 시설로 중첩되지 않습니다. PC는 마우스, 휴대폰은 가로 터치를 사용합니다. 전장 우측 +/−로 확대·축소하고 전장을 드래그해 이동합니다. ⌖로 전체 보기를 복원합니다. Esc로 배치를 취소합니다. 효과 설정은 해당 브라우저에 저장합니다.

## 시설 해금

| 클리어 웨이브 | 해금 시설 |
| --- | --- |
| 시작 | 기관총, 보병 막사, 은행 |
| 5 | 산탄 포탑, 냉각탑 |
| 10 | 저격탑, 돌격병 기지 |
| 15 | 박격포, 보급소 |
| 20 | 화염탑, 중화기 기지 |
| 25 | 전기탑, 의무소 |
| 30 | 미사일탑, 드론 기지 |
| 35 | 레일건, 플라스마탑 |

모든 시설은 기본형 → 강화형 → 정예형 → 최종형으로 강화됩니다. 공격·병력 시설은 무장 외형도 변화하며 은행은 수익이 증가합니다. 능력치와 가격은 `shared/catalog.js`, 지도는 `shared/maps.js`에서 관리합니다.

## 협동과 재접속

진행 중에도 최대 4명까지 입장합니다. 뒤늦게 들어오면 진행도 기반 초기 자금과 현재 팀 해금을 적용합니다. 접속 인원 변화는 이후 생성하는 적의 난이도에 적용합니다. 같은 브라우저·기기에서 탭 재열기, 새로고침 또는 일시 연결 끊김 후 2분 이내에는 자신의 찌와 시설을 복원합니다. 재접속 토큰은 해당 브라우저의 localStorage에 보관하고 공유 URL에는 넣지 않습니다. 연결이 끊긴 자리는 2분간 보존되며 만료 후 해당 플레이어 시설·병사를 제거합니다. 모두 연결이 끊기면 전투는 일시 정지합니다.

방 상태는 **서버 메모리**에만 있습니다. 서버 재시작·재배포 시 방과 기록은 사라집니다. 영구 랭킹·계정·음성 채팅은 포함하지 않습니다.

## 검증

```sh
npm test
npm run test:browser
```

첫 명령은 게임 규칙과 실제 WebSocket 통합 테스트를 실행합니다. 브라우저 검증은 시스템 Chromium을 `/usr/bin/chromium`에서 사용합니다. 다른 경로는 `CHROMIUM_PATH`로 지정할 수 있습니다. 시스템 브라우저가 없다면 `npx playwright install chromium`으로 설치 후 실행 파일 경로를 지정합니다. 브라우저 테스트는 포트 3000의 서버를 재사용하거나 자동 시작합니다. 다른 프로젝트의 서버가 이 포트를 사용하는 경우 먼저 종료하거나 설정을 변경하세요.

브라우저 테스트는 1인 시작, 배치, 강화, 돈 차감, 잠긴 시설, 웨이브 시작, 모바일, 공유, 새로고침·탭 재열기 복원, 2인 상태 공유, 실제 병사·피해 효과와 지연된 건설 응답을 검사합니다. 스크린샷은 `test-results/`에 생성됩니다.

## 카톡 친구에게 실제로 보내려면

인터넷에서 접속 가능한 **HTTPS + WebSocket** 호스팅에 배포해야 합니다. 로컬 서버 실행만으로 친구가 접속할 수 있는 공개 주소가 생기지는 않습니다. 공개 호스트에서 `npm ci --omit=dev` 후 `npm start`를 실행하고, HTTPS 리버스 프록시에서 WebSocket Upgrade와 동일한 Host 헤더를 전달하세요. 정적 파일 전용 호스팅만으로는 실시간 서버를 실행할 수 없습니다.

한 프로세스가 모든 방을 관리하므로 최초 배포는 단일 인스턴스와 연결 유지 가능한 서버를 사용하세요. 여러 인스턴스의 방 공유나 자동 서버리스 중단은 지원하지 않습니다. 방은 최대 100개이며 요청 크기·초당 요청·소환 수·이펙트 개수를 제한합니다. 실제 공개 배포의 용량 및 카카오톡 인앱 브라우저 실기기 검증은 별도입니다.

`Dockerfile`로 단일 서버 이미지를 빌드할 수 있습니다. 배포 서비스 계정 생성, 유료 결제, 공개 게시·Git push는 자동으로 하지 않습니다.

## 알려진 제한

이미 사용 중인 포트로 두 번째 서버를 띄우면 시작 오류가 발생합니다. 시작 실패의 오류·타이머 정리 개선은 보류했으므로 포트당 한 프로세스만 실행하세요. 고웨이브 장기 밸런스와 카카오톡 인앱 브라우저 실기기 테스트는 아직 수행하지 않았습니다.

## 다운로드형 1인 체험판

```sh
npm run build:solo
npm run test:solo
```

`dist/last-outpost-solo.html`을 브라우저에서 열면 별도 Node 설치나 서버 없이 1인 플레이를 할 수 있습니다. 원래 게임의 시설·전투·지도 규칙과 화면을 묶었으며 외부 파일·WebSocket 연결이 필요하지 않습니다. 닉네임 입력 후 작전 시작 → 시설 배치 → 방어 시작 순으로 진행합니다. 창을 닫거나 새로 열면 진행은 초기화됩니다. 이 체험판의 친구 초대는 비활성화하며 실시간 협동은 기존 서버 버전에서 제공합니다. 휴대폰 파일 앱에 따라 HTML의 JavaScript 실행을 막을 수 있으므로 가능하면 PC 브라우저에서 여세요.

관리형 Chromium은 file URL 접근을 정책상 차단하므로 자동 테스트는 HTML 내용을 직접 로드해 외부 네트워크 요청 없이 건설, 강화, 웨이브 실행을 검증합니다. 다운로드 후 사용자 기기에서의 파일 실행 자체는 별도 실기기 확인이 필요합니다.
