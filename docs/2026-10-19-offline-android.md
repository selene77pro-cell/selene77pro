# 뀨겜1: 휴대폰 파일 실행 점검

사용자는 안드로이드에서 파일을 받아 닉네임 입력 후 '혼자 새 방 시작'을 눌러도 입장되지 않는다고 보고했다. 기기 콘솔은 제공되지 않았으므로 실제 기기의 원인은 확정하지 않는다. 시스템 디버깅 스킬을 적용해 경로와 브라우저 의존 API를 조사한다.

재현1: history.replaceState가 SecurityError를 던지는 파일/content URL 보기 환경을 모사하면 시작 버튼에서 게임 UI로 넘어가지 않는다. 재현 테스트 RED 확인 후 주소 변경을 try/catch로 격리하여 게임 상태와 입장이 계속되도록 수정했고 기존 오프라인 게임 검사와 함께 2개가 통과했다.

추가 조사: 구형 브라우저에 없는 structuredClone과 Object.hasOwn도 프로필 초기화/복원 단계에서 사용된다. 각 API를 제거한 테스트로 실패를 확인하고, 오프라인 JSON 프로필 데이터에 한정한 호환 동작을 제공한다.

사용자의 최종 파일명 지시: '뀨겜1.html'. 이전 이름의 파일도 생성하되 새 파일과 화면 표시로 구분한다. 스크립트 차단·실행 오류가 있으면 시작 화면에 설명을 표시하여 버튼이 무반응인 상태를 숨기지 않는다. JavaScript를 비활성화하는 HTML 미리보기 앱 자체를 파일 코드로 활성화할 수는 없다. 실제 안드로이드/카톡 파일 뷰어 실행은 별도 확인이 필요하다.

브랜드 요청: 이미지 생성 도구로 Q·군모·방패를 조합한 전용 마크를 생성해 public/qqu-icon.png에 보관했다. 서버는 PNG MIME을 제공한다. 단일 HTML에는 CSS 변수로 이미지를 한 번만 포함하고 화면 로고와 탭 아이콘에서 재사용하므로 별도 파일 전송은 필요 없다. HTML의 다운로드 목록/탐색기 아이콘은 운영체제의 연결 앱 표시이므로 바꾸었다고 주장하지 않는다.

구형 API 두 가지를 각각 제거한 테스트도 RED 확인 후 JSON 프로필에 한정된 호환 동작을 추가했다. 주소 변경 제한과 함께 초기 4개 검사가 통과했다. 스크립트 비활성화와 런타임 오류는 정적 안내 및 오류 표시로 구분한다. 자동 검사에서 noscript 태그 해석은 setContent/CDP 환경의 파서 플래그와 달라질 수 있어, 실제 표시되는 정적 안내와 숨겨진 게임 상태를 검사한다.

최종 검증: 서버54/54, 브라우저18/18, 오프라인6/6 통과. 생성된 단일 HTML의 게임 제목·실행 준비 안내·탭 PNG 아이콘·실제 패널 색·건설 메뉴를 검증했고 전용 마크가 표시된 스크린샷을 확인했다. 배포용 뀨겜1.zip은 게임 HTML 한 개만 포함하며 독립적인 Python 표준 ZIP 리더로 UTF-8 파일명·CRC·원본 HTML 일치를 확인했다. Node 기본 zlib만 사용하는 ZIP 생성기를 build:solo에 연결하여 향후 수정 시 아카이브가 낡지 않게 한다. 아직 사용자의 실제 안드로이드 실행은 확인하지 못했다.
